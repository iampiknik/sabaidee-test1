# Dashboard ร้านยาสบายดีฟาร์มาซี

โครงโปรเจกต์ React + TypeScript + Vite สำหรับ deploy บน GitHub Pages
(รายละเอียดเต็มดู `dashboard-spec.md` ที่ส่งมอบแยกไว้ก่อนหน้า)

## สถานะปัจจุบัน (prototype)

- ✅ โครงโปรเจกต์ Vite + React + TS ใช้งานได้ (`npm run dev`, `npm run build` ผ่านแล้ว)
- ✅ Parser ต้นแบบสำหรับไฟล์ **นับเงินรายวัน.xlsx** (`src/lib/parsers/dailyCashWorkbook.ts`)
  ทดสอบกับไฟล์ตัวอย่างจริงของร้านแล้ว ใช้งานได้
- ✅ หน้าจอ **ยอดขาย** (`src/pages/SalesPage.tsx`) — นำเข้าไฟล์นับเงินรายวันในเบราว์เซอร์,
  แสดง KPI, กราฟยอดขายรายวัน, กราฟแยกช่องทางรับเงินระดับวัน, ตารางละเอียด, ตัวกรองช่วงวันที่
  (ยังไม่ได้ต่อ IndexedDB — ข้อมูลหายเมื่อรีเฟรชหน้า ต้องนำเข้าไฟล์ใหม่ทุกครั้ง)
- ⬜ Parser สำหรับรายงานขาย/รับเข้า/สินค้า (Crystal Reports layout) — ยังไม่ทำ (หน้ายอดขายจึง
  ยังไม่มี "จำนวนบิล" และ "สินค้าขายดี" ตามที่ระบุไว้ในหน้าจอเป็น "ข้อมูลไม่เพียงพอ")
- ⬜ IndexedDB layer (บันทึกข้อมูลข้ามเซสชัน), หน้าจออีก 8 เมนู — ยังไม่ทำ

## วิธีทดสอบ parser กับไฟล์ตัวอย่างของคุณเอง

```bash
npm install
npm run test:parse-daily-cash -- "/path/to/นับเงินรายวัน.xlsx"
```

**ห้าม commit ไฟล์ .xlsx/.xls ของร้านจริงเข้า repo นี้เด็ดขาด** — `.gitignore` กันไว้แล้ว
แต่ควรระวังตอนโยนไฟล์เข้าโฟลเดอร์โปรเจกต์ด้วย

## ผลการทดสอบกับไฟล์ตัวอย่างจริง (สรุป)

รันกับไฟล์ นับเงินรายวัน.xlsx ของร้าน (ช่วงข้อมูล 31 พ.ค. 2568 – 24 ก.ย. 2569):

| ชีต | ผลลัพธ์ | หมายเหตุ |
|---|---|---|
| นับเงิน | 482 แถว, ยอดขายรวม ~4.3 ล้านบาท | แปลงปี พ.ศ.→ค.ศ. อัตโนมัติสำเร็จทุกแถว (ไม่มี warning), ตัดแถวเปล่าที่เตรียมไว้ล่วงหน้าถึงสิ้นปีออกให้แล้ว |
| บช รับ-จ่าย | 440 แถว | **พบวันที่ผิดปกติจำนวนมาก** (ปีถูกอ่านเป็น 1964/1969 ฯลฯ) ต้องให้ผู้ใช้ตรวจสอบด้วยมือ |
| ของหมด (watchlist) | 773 แถว | โครงสร้างหลวม เป็นโน้ตอิสระของร้าน |
| ของหมด (stock take) | 0 แถวในไฟล์ตัวอย่างนี้ | คอลัมน์ เช็คสต็อก/จริง/คอม/ขาด-หาย ยังไม่มีข้อมูลกรอกในไฟล์นี้ — โครงสร้างรองรับไว้แล้ว รอไฟล์ที่มีข้อมูลจริง |
| จ่ายค่าของ | 3,279 แถว | ดึงเฉพาะคอลัมน์บัญชีเจ้าหนี้ **ไม่แตะคอลัมน์ชื่อ/เบอร์โทรลูกค้าที่ปนอยู่ในชีตนี้เลย** ตามกฎความเป็นส่วนตัว |

รวม warning ทั้งหมด 2,093 รายการ (แทบทั้งหมดคือปัญหาวันที่ในสองชีตหลัง)

**ข้อค้นพบสำคัญที่ต่างจากที่ประเมินไว้ก่อนหน้า:** ปัญหาวันที่ผิดปกติในชีต "บช รับ-จ่าย" และ
"จ่ายค่าของ" เกิดขึ้น**เกือบทุกแถว** ไม่ใช่เฉพาะบางจุด — สาเหตุคือมีการพิมพ์ปีแบบย่อ 2 หลัก
(เช่น "64") แล้ว Excel ตีความเป็น ค.ศ. 1964 เอง ซึ่งเดาปีที่ถูกต้องคืนแบบอัตโนมัติไม่ได้อย่าง
ปลอดภัย ระบบเก็บ record ไว้ (ไม่ทิ้งข้อมูล) แต่ตั้ง `date: null` และใส่ warning ให้ผู้ใช้แก้เอง
ในหน้านำเข้าข้อมูล — เมนู "นำเข้าข้อมูล" ในเวอร์ชันจริงต้องมี UI ให้แก้ไขวันที่ทีละแถวหรือ
เลือกแก้เป็นชุดสำหรับ pattern นี้โดยเฉพาะ เพราะจำนวนแถวที่ต้องแก้มีหลักพันแถว

## โครงสร้างไฟล์ที่เกี่ยวข้อง

```
src/
  types/schema.ts                     — type ตรงตาม data model ใน dashboard-spec.md
  lib/parsers/normalizeThaiDate.ts    — แปลง พ.ศ./ค.ศ. + ตรวจจับปีผิดปกติ
  lib/parsers/dailyCashWorkbook.ts    — parser ไฟล์นับเงินรายวัน (4 ชีต)
scripts/test-parse-daily-cash.ts      — รัน parser กับไฟล์จริงแล้ว log ผลลัพธ์
```

## ขั้นต่อไป

1. เขียน parser สำหรับรายงานขาย-แยกตามบิลขาย (ซับซ้อนสุด เพราะเป็น Crystal Reports
   layout หลายชีต/ไฟล์ใหญ่ ต้องรันผ่าน Web Worker)
2. ต่อ IndexedDB layer (แนะนำ `idb` package) ตาม schema ที่มี
3. ออกแบบหน้า "นำเข้าข้อมูล" ให้รองรับการแก้ไขวันที่ผิดปกติทีละแถว/เป็นชุด ตามที่เจอจริง
4. เริ่มหน้าจอ "ภาพรวมกิจการ" เป็นหน้าแรก

## Deploy ขึ้น GitHub Pages

มี `.github/workflows/deploy.yml` เตรียมไว้แล้ว build อัตโนมัติทุกครั้งที่ push เข้า branch `main`
และตั้ง `--base` ให้ตรงกับชื่อ repo อัตโนมัติ (ยกเว้น repo ชื่อ `<username>.github.io` ให้แก้เป็น `--base=/`)
ดูขั้นตอนละเอียดในแชทที่คุยกัน หรือถามซ้ำได้ทุกเมื่อ
